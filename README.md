# BinFloater · 安卓二进制悬浮窗

> **这个项目全部由 AI 制作。** 代码、测试、文档都是 AI 写的，人类只负责提需求和真机验收。

一个常驻桌面的小悬浮球。点一下展开面板，把剪切板里的 0/1 串翻译成文字，或者把文字转成二进制。纯本地，不联网，不要任何敏感权限。

---

## 它解决什么问题

有些场景需要手打二进制：CTF 题面、串口日志、协议调试、编码练习。一边看一边手动敲 `01101000 01100101` 再翻成 `he`，效率低还容易错。

这个工具的做法是：剪切板里出现 0/1 串，点一下悬浮球，面板浮起来，直接告诉你这串二进制是什么字。反过来，输入一段文字，立刻给出它的 UTF-8 二进制。

---

## 界面

| 悬浮球 | 面板 |
|---|---|
| 桌面边缘的小方块，显示 `01` / `BIN` | 点开后是完整面板：输入框、输出框、状态行、三个按钮 |

| 文字 → 二进制 | 二进制 → 文字 |
|---|---|
| 输入 `hi` → `01101000 01101001` | 输入 0/1 串 → 还原出原文字 |

## 功能

### 核心

- **双向转换**：文字 ↔ 二进制，`⇄` 一键切方向
- **点一下读剪切板**：点悬浮球展开面板时，自动把剪切板内容读进来并翻译
- **复制结果**：转好的内容一键回写剪切板
- **自动识别方向**：剪切板里是 0/1 串就按「二进制 → 文字」处理，否则按「文字 → 二进制」

### 编码细节

- **UTF-8 优先**，解不出来依次回退 GBK → Big5 → Latin-1
- 认多种分隔符：空格、逗号、分号、冒号、下划线、短横线、斜杠、竖线，也认完全连写
- 认 `0b` 前缀
- 阈值保护：**少于 16 位不当二进制**；少于 24 位还要求同时含 0 和 1，避免把 `2024` 这种数字误判成二进制

### 悬浮窗

- 可拖动，吸附在屏幕边缘
- 折叠时只占一个小方块
- 面板位置跟随悬浮球
- 常驻通知栏（Android 前台服务要求），可随时关掉

## 为什么不能自动监听剪切板

这是 Android 的系统限制，不是实现偷懒。

**Android 10（API 29）起，没有输入焦点的应用读剪切板一律返回空。** Android 12 之后 `hasPrimaryClip()` 甚至直接返回 false。能绕过的办法只有三条：

| 方案 | 代价 |
|---|---|
| 抢焦点（本项目的做法） | 读之前得先弹出获得焦点的窗口，会打断当前输入 |
| `READ_LOGS` 权限 | 需要 adb 授权，普通用户装不了 |
| Shizuku | 需要额外装一个 App 并每次重启后重新授权 |

所以这个项目选了第一条，但把它做成**按需触发**：不常驻监听，只有你点悬浮球那一刻才抢焦点读一次。代价是点的那一下会收起当前键盘，换来的是不申请任何敏感权限、不常驻后台耗电、不读取你没让它读的东西。

## 快速开始

### 装 APK

从 [Releases](../../releases) 下载 `BinFloater.apk`，装好后：

1. 打开 App，点「① 授予悬浮窗权限」，在系统设置里允许「显示在其他应用上层」
2. 回到 App，打开「悬浮窗」开关
3. 桌面边缘出现小方块，点它展开面板

### 自己构建

需要 JDK 17+ 和 Android SDK（platform-tools、platforms;android-36、build-tools;36.0.0）。

```bash
# 默认从 /f/AndroidSdk 找 SDK，可用 ANDROID_SDK 环境变量覆盖
bash build.sh

# 产物
build/BinFloater.apk
```

不依赖 Gradle。构建脚本手工调 `aapt2` → `javac` → `d8` → 打 zip → `zipalign` → `apksigner`，从零到出包 3 秒。

### 跑测试

```bash
bash run_tests.sh
```

80 项断言，分两组：编解码核心 37 项、静态审查 43 项。

## 技术上的几个选择

**不用 Gradle。** 这个项目只有 3 个源文件、4 个资源，Gradle 拉依赖动辄几百 MB 还要联网。手工调 `aapt2` / `javac` / `d8` 一条流水线下来，从零到出包 3 秒。

**编解码核心零 Android 依赖。** `BinCore.java` 全是 static 方法，不 import 任何 `android.*`，所以能直接在桌面 JVM 上跑单测，不需要 Robolectric 也不需要真机。

**面板必须拿到焦点。** 这不是 bug 是特性——只有获得焦点的窗口读剪切板才不被系统拦。所以面板窗口不能加 `FLAG_NOT_FOCUSABLE`，只有气泡可以加。静态审查里专门有一条守着这个约束。

---

## 已知限制

- **只在 ColorOS 16 / Android 16 真机上验证过**，其他 ROM 未测
- 点悬浮球会收起当前键盘（抢焦点的必然代价）
- 面板宽度固定 292dp，小屏手机上可能显得宽
- 不支持自动监听，必须手动点
- 剪切板内容超过 64KB 会被系统截断
